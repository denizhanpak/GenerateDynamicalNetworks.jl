Results

Every backend was run on the example networks and put through the acceptance protocol (The acceptance rule). The tables on this page are built from the stored runs in benchmarks/results/ each time the documentation is built.

The stored runs are 98 cases, made at commit 254438c on 14 threads, on 2026-11-14.

The suite

Each case is one backend on one network at one noise level.

  • Most backends run the six networks with one-way edges (Example networks) at noise 0.001 and 0.1.
  • Synchrony and Hopfield also run a three-state ring with dwells 1, 3 and 10.
  • The CTRNN backend runs all ten networks, including the four with two-way edges, at noise 0.1 only.

A case passes when the fitted model passes all three checks. Times are for the whole suite on that backend: all its fits, and all its checks.

How the cases fail

A case can fail one, two or three of its checks. Failing one check by a small margin is what the branch rule does to a correct model from time to time (How strict the branch rule is); failing all three points to a consistent error.

Reproduction of the prototype

The package was ported from a research prototype. To check the port, each backend was refitted with the prototype's settings on one network and compared with the prototype's stored result.

  • Equal numbers: the refit follows the same random-number path, so every stored number must be equal.
  • Same band verdicts: the refit is a different model (one solver setting was fixed in the Hopfield backend, and the prototype's special layout for the three-state ring wasn't ported to the synchrony backend). Every state's mean dwell must then be on the same side of the 5% band as in the stored result, on each check.
